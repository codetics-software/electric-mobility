# OCPP 2.x June 2026 errata that affect implementation

Use this with the [2.0.1](ocpp-2.0.1.md) or [2.1](ocpp-2.1.md) guide and the relevant [message card](messages/). It summarizes selected corrections in the OCA edition 4 (2.0.1) and edition 2 (2.1) June 2026 errata. Both errata state that they do **not** change OCPP message schemas; some corrections still change valid behavior. A schema-valid message can therefore fail a corrected use-case requirement.

| Area | Implementation rule |
|---|---|
| Remote start, both versions | `RequestStartTransactionRequest.evseId` is optional on the wire. A CSMS must nevertheless be able to send it. A station unable to choose an EVSE may reject a request without one; retry with an explicit, authorized `evseId` after reconciling the first attempt. |
| Unknown RPC message type, both versions | Ignore an unknown message-type number as a whole. Do not send the deprecated `MessageTypeNotSupported` error. Keep this separate from an unsupported known CALL action, malformed JSON, and failed authentication. |
| Reset during a transaction, both versions | Recheck the corrected B12 behavior: a station may wait for cable disconnection before reset. Do not declare reset complete solely from a successful immediate response. |
| Firmware verification, both versions | The corrected signed-firmware requirement removes the ECSchnorr option and clarifies station signature verification. Confirm the configured signing algorithm and verified artifact before reporting installation success. |
| Meter units, 2.0.1 | Apply the clarified `UnitOfMeasureType` meaning when converting readings; preserve the original unit and multiplier as evidence. |
| Transaction retries, both versions | June test corrections apply retry behavior to `TransactionEventRequest` after EV-side energy-transfer suspension. Maintain transaction identity and sequence evidence across retry/reconnect; do not create a second session. |
| Periodic stream, 2.1 | `StreamDataElementType.t` is an offset **in seconds** from `NotifyPeriodicEventStream.basetime`. The errata correct an invalid Part 4 example; use the SEND card's schema, not the older example. |
| DER control, 2.1 | Treat `LimitMaxDischargeType.pctMaxDischargePower` as required by the corrected prose even if its schema marks it optional. `PowerMonitoringMustTrip` remains in `DERControlEnumType` for compatibility but is invalid as a standalone control; use it only within `LimitMaxDischarge`. |
| Device Model, 2.1 | `ISO15118Ctrlr.ProtocolEnabled[]` is a new optional variable paired with `ProtocolSupported[]`. Discover support before setting it; do not assume an older station exposes it. |

The 2.1 corrections also clarify local load balancing limits, reset/transaction resume, and several certification cases. For those features, inspect the applicable use case and test profile before asserting conformance. The [OCA protocol page](https://openchargealliance.org/protocols/open-charge-point-protocol/) provides the normative edition and errata; this guide keeps routine implementation self-contained.
